## `add_months`

Returns the date that is `num_months` months after `start_date`. A negative `num_months` moves the date backwards. DataFusion has no built-in `add_months`. If the day of the month does not exist in the result month, the last day of that month is returned (so subtracting 5 months from 2016-07-30 gives 2016-02-29). Returns NULL if either input is NULL. A result outside the supported date range returns an error. `num_months` must be an INT. Integer literals are BIGINT in DataFusion, so cast them (for example `1::INT`; see [#97](https://github.com/apache/datafusion-spark/issues/97)). `start_date` must be a DATE; strings are not implicitly cast as they are in Spark ([#41](https://github.com/apache/datafusion-spark/issues/41)).

```sql
add_months(start_date, num_months)
```

### Arguments

- **start_date**: DATE expression. NULL returns NULL.
- **num_months**: INT number of months to add. Negative values subtract months. NULL returns NULL.

### Example

```sql
> SELECT add_months(DATE '2016-07-30', 1::INT);
2016-08-30
> SELECT add_months(DATE '2016-07-30', -5::INT);
2016-02-29
> SELECT add_months(DATE '2016-07-30', NULL::INT);
NULL
```

## `date_diff`

Returns the number of days from `start_date` to `end_date`, as an INT. The result is negative when `end_date` is before `start_date`. DataFusion has no built-in `date_diff`. Strings and timestamps are cast to DATE first, so the time of day is ignored. Returns NULL if either input is NULL.

```sql
date_diff(end_date, start_date)
```

### Arguments

- **end_date**: DATE, TIMESTAMP or string expression. NULL returns NULL.
- **start_date**: DATE, TIMESTAMP or string expression. NULL returns NULL.

### Example

```sql
> SELECT date_diff(DATE '2009-07-31', DATE '2009-07-30');
1
> SELECT date_diff('2009-07-30', '2009-07-31');
-1
> SELECT date_diff(TIMESTAMP '2009-07-31 23:45:01', TIMESTAMP '2009-07-30 12:34:56');
```

## `date_from_unix_date`

Returns the date that is `days` days after 1970-01-01. This is the inverse of `unix_date`. DataFusion has no built-in equivalent. Negative values give dates before the epoch. Any INT is a valid date. Other numeric and string inputs are cast to INT first, which truncates fractions and raises an error if the value is out of the INT range or is not a valid number. These errors match Spark with ANSI mode enabled. With ANSI mode disabled, Spark wraps an out-of-range BIGINT and returns NULL for a malformed string, while this function still errors (see https://github.com/apache/datafusion-spark/issues/88). Returns NULL if the input is NULL.

```sql
date_from_unix_date(days)
```

### Arguments

- **days**: Number of days since 1970-01-01, as an INT. Other integer, floating-point, decimal and string inputs are cast to INT. BOOLEAN is rejected. NULL returns NULL.

### Example

```sql
> SELECT date_from_unix_date(1000);
1972-09-27
> SELECT date_from_unix_date(-1);
1969-12-31
> SELECT date_from_unix_date(NULL);
NULL
```

## `date_part`

Extracts a field from a date or timestamp, as an INT. Unlike DataFusion's `date_part`, it accepts Spark's field names and abbreviations (case-insensitive), and `DAYOFWEEK`/`DOW` counts from 1 (Sunday) to 7 (Saturday) where DataFusion's `dow` counts from 0 (Sunday). `DAYOFWEEK_ISO`/`DOW_ISO` counts from 1 (Monday) to 7 (Sunday), and `YEAROFWEEK` is the ISO week-numbering year. A field name Spark does not accept (such as `QUARTERS` or `DAYOFYEAR`) is an error. A NULL field or source returns NULL. `SECOND` returns whole seconds; Spark returns DECIMAL(8, 6) including the fraction of a second.

```sql
date_part(field, source)
```

### Arguments

- **field**: String literal naming the field to extract: `YEAR` (`Y`, `YEARS`, `YR`, `YRS`), `YEAROFWEEK`, `QUARTER` (`QTR`), `MONTH` (`MON`, `MONS`, `MONTHS`), `WEEK` (`W`, `WEEKS`), `DAY` (`D`, `DAYS`), `DAYOFWEEK` (`DOW`), `DAYOFWEEK_ISO` (`DOW_ISO`), `DOY`, `HOUR` (`H`, `HOURS`, `HR`, `HRS`), `MINUTE` (`M`, `MIN`, `MINS`, `MINUTES`) or `SECOND` (`S`, `SEC`, `SECONDS`, `SECS`). NULL returns NULL.
- **source**: DATE or TIMESTAMP expression. NULL returns NULL.

### Example

```sql
> SELECT date_part('YEAR', DATE '2000-01-01');
2000
> SELECT date_part('DOW', DATE '2000-01-01');
7
> SELECT date_part('MINS', TIMESTAMP '2000-01-01 12:30:45');
30
> SELECT date_part('year', NULL::TIMESTAMP);
NULL
```

### Alternative Syntax

```sql
datepart(field, source)
```

### Aliases

- datepart

## `date_trunc`

Returns `ts` truncated to the unit given by `fmt`, with the same type as `ts`. Unlike DataFusion's `date_trunc`, it also accepts Spark's unit aliases `yyyy` and `yy` for year, `mon` and `mm` for month and `dd` for day, and it truncates a timestamp with a time zone in the session time zone (`datafusion.execution.time_zone`) rather than the timestamp's own time zone. A string `ts` is cast to a timestamp. Returns NULL if `ts` is NULL. `fmt` must be a constant string: a NULL `fmt` is a planning error and an unsupported `fmt` is an execution error, where Spark returns NULL for both.

```sql
date_trunc(fmt, ts)
```

### Arguments

- **fmt**: Constant string unit, case-insensitive: `year` (`yyyy`, `yy`), `quarter`, `month` (`mon`, `mm`), `week` (truncates to Monday), `day` (`dd`), `hour`, `minute`, `second`, `millisecond` or `microsecond`.
- **ts**: Timestamp expression to truncate. A string is cast to a timestamp. NULL returns NULL.

### Example

```sql
> SELECT date_trunc('YEAR', '2015-03-05T09:32:05.123456'::timestamp);
2015-01-01T00:00:00
> SELECT date_trunc('MM', '2015-03-05T09:32:05.123456'::timestamp);
2015-03-01T00:00:00
> SELECT date_trunc('HOUR', '2015-03-05T09:32:05.123456'::timestamp);
2015-03-05T09:00:00
> SELECT date_trunc('MILLISECOND', '2015-03-05T09:32:05.123456'::timestamp);
```


## `from_utc_timestamp`

Treats `ts` as a UTC wall-clock time and returns the wall-clock time in time zone `tz`. DataFusion has no built-in equivalent. A string `ts` is cast to a timestamp, so a string with an offset is first converted to UTC. The result has the same type as `ts`, including any time zone it carries. Returns NULL if either argument is NULL. `tz` accepts Spark's spellings: region IDs, offsets such as `+01:00`, `GMT+1`, `UTC+1:2` and `UT-010203`, Java short IDs such as `PST`, and legacy `SystemV/` IDs. An offset beyond 18 hours or an unknown zone is an error. Differences from Spark: `tz` is only parsed for rows where both arguments are non-NULL, so an invalid constant `tz` can return NULL where Spark raises an error; conversion is limited to Chrono's calendar range, which is narrower than the range Spark implements but covers Spark's documented range; and region rules from `chrono-tz` may differ after 2099, because it does not extrapolate later daylight saving time transitions.

```sql
from_utc_timestamp(ts, tz)
```

### Arguments

- **ts**: Timestamp expression, interpreted as UTC. A string is cast to a timestamp. NULL returns NULL.
- **tz**: String time zone to convert to. NULL returns NULL.

### Example

```sql
> SELECT from_utc_timestamp('2016-08-31'::timestamp, 'Asia/Seoul');
2016-08-31T09:00:00
> SELECT from_utc_timestamp('2018-03-13T06:18:23+02:00', 'America/New_York');
2018-03-13T00:18:23
> SELECT from_utc_timestamp('2024-07-01T00:00:00'::timestamp, 'GMT+1');
2024-07-01T01:00:00
> SELECT from_utc_timestamp('2016-08-31'::timestamp, NULL);
NULL
```

## `make_date`

Creates a date from `year`, `month` and `day` fields. Years from -999999999 to 999999999 are accepted (year 0 is 1 BC), as long as the date fits the DATE range. When the fields do not form a valid date (for example month 13 or February 29 in a non-leap year), the function returns NULL, or raises DATETIME_FIELD_OUT_OF_BOUNDS when `datafusion.execution.enable_ansi_mode` is true. A valid date outside the DATE range (before -5877641-06-23 or after +5881580-07-11) raises ARITHMETIC_OVERFLOW in both modes, as in Spark. Other numeric and string inputs are cast to INT first, which truncates fractions and raises an error if the value is out of the INT range or is not a valid number. These errors match Spark with ANSI mode enabled. With ANSI mode disabled, Spark wraps an out-of-range BIGINT or DECIMAL, truncates a string with a fractional part, returns NULL for a malformed string or a floating-point value out of the INT range, and casts NaN to 0, while this function still errors (see https://github.com/apache/datafusion-spark/issues/88). Returns NULL if any input is NULL. DataFusion's built-in `make_date` differs: it raises an error for an invalid date regardless of ANSI mode, accepts only integer and string arguments, and is limited to years -262143 to 262142.

```sql
make_date(year, month, day)
```

### Arguments

- **year**: The year, from -999999999 to 999999999, as an INT. Other integer, floating-point, decimal and string inputs are cast to INT. NULL returns NULL.
- **month**: The month of the year, from 1 (January) to 12 (December), as an INT. NULL returns NULL.
- **day**: The day of the month, from 1 to 31, as an INT. NULL returns NULL.

### Example

```sql
> SELECT make_date(2013, 7, 15);
2013-07-15
> SELECT make_date(2019, 7, NULL);
NULL
> SELECT make_date(2023, 2, 29);
NULL
```

## `make_dt_interval`

Returns a day-time interval built from days, hours, minutes and seconds. DataFusion has no built-in equivalent. All arguments are optional from the right and default to 0, so `make_dt_interval()` is a zero interval. Components can be negative and are added together, so `make_dt_interval(1, -24)` is zero. The result is a `Duration(Microsecond)` rather than an Arrow interval, because Arrow's day-time interval only has millisecond precision while Spark's has microsecond precision. Returns NULL if any argument is NULL or `secs` is NaN or infinite. Overflow returns NULL, where Spark raises an error ([#20](https://github.com/apache/datafusion-spark/issues/20)). Unlike Spark, where `secs` is a DECIMAL(18, 6), `secs` is cast to DOUBLE and the fraction is rounded to microseconds.

```sql
make_dt_interval([days[, hours[, mins[, secs]]]])
```

### Arguments

- **days**: Integer number of days, cast to INT. NULL returns NULL.
- **hours**: Integer number of hours, cast to INT. NULL returns NULL.
- **mins**: Integer number of minutes, cast to INT. NULL returns NULL.
- **secs**: Numeric number of seconds, which may have a fraction, cast to DOUBLE. NULL, NaN or an infinite value returns NULL.

### Example

```sql
> SELECT make_dt_interval(1, 12, 30, 1.001001);
1 days 12 hours 30 mins 1.001001 secs
> SELECT make_dt_interval(2);
2 days 0 hours 0 mins 0.000000 secs
> SELECT make_dt_interval(100, NULL, 3);
NULL
```

## `make_interval`

Returns an interval built from years, months, weeks, days, hours, minutes and seconds. DataFusion has no built-in equivalent. All arguments are optional from the right and default to 0, so `make_interval()` is a zero interval. Returns NULL if any argument is NULL or `secs` is NaN or infinite. Overflow returns NULL; ANSI mode is not applied. Unlike Spark, where `secs` is a DECIMAL(18, 6), `secs` is cast to DOUBLE and the fraction is rounded to nanoseconds.

```sql
make_interval([years[, months[, weeks[, days[, hours[, mins[, secs]]]]]]])
```

### Arguments

- **years**: Integer number of years, cast to INT. NULL returns NULL.
- **months**: Integer number of months, cast to INT. NULL returns NULL.
- **weeks**: Integer number of weeks, cast to INT. NULL returns NULL.
- **days**: Integer number of days, cast to INT. NULL returns NULL.
- **hours**: Integer number of hours, cast to INT. NULL returns NULL.
- **mins**: Integer number of minutes, cast to INT. NULL returns NULL.
- **secs**: Numeric number of seconds, which may have a fraction, cast to DOUBLE. NULL, NaN or an infinite value returns NULL.

### Example

```sql

```

## `make_time`

Creates a time of day from hour, minute and second fields. The result is a `Time64(Nanosecond)` with microsecond precision, like Spark's `TIME(6)`. Returns NULL if any argument is NULL. Out-of-range fields raise a `DATETIME_FIELD_OUT_OF_BOUNDS` error whether or not ANSI mode is enabled. Seconds that are negative or above 2147483647 are checked first, then hour, minute and second, so the error names the same field as Spark's. Arguments are cast to INT, INT and DECIMAL(16, 6) with DataFusion's cast rather than Spark's, so a value the cast cannot represent (an integer outside the INT range, a malformed string, seconds that do not fit DECIMAL(16, 6), NaN or Infinity) raises a cast error in both ANSI modes. With ANSI mode off Spark wraps the integer or returns NULL instead, and it returns NULL for NaN and Infinity in both modes (https://github.com/apache/datafusion-spark/issues/88).

```sql
make_time(hour, minute, second)
```

### Arguments

- **hour**: Hour of the day, 0 to 23. Numeric and string values are cast to INT, and a fractional number is truncated.
- **minute**: Minute of the hour, 0 to 59. Numeric and string values are cast to INT, and a fractional number is truncated.
- **second**: Second of the minute with an optional fraction, 0 to 59.999999. Numeric and string values are cast to DECIMAL(16, 6), so extra fractional digits are rounded half up (59.9999995 becomes 60 and is out of range).

### Example

```sql
> SELECT make_time(6, 30, 45.887);
06:30:45.887
> SELECT make_time(23, 59, 59.999999);
23:59:59.999999
> SELECT make_time(1, 18, NULL);
NULL
> SELECT make_time(24, 18, 19.87);
-- error: Invalid value for HourOfDay (valid values 0 - 23): 24
```

## `next_day`

Returns the first date after `start_date` that falls on `day_of_week`. The result is always later than `start_date`: if `start_date` is already that day, the date one week later is returned. DataFusion has no built-in `next_day`. Strings and timestamps are cast to DATE first. next_day(start_date, day_of_week)

### Example

```sql
> SELECT next_day(DATE '2015-01-14', 'TU');

> SELECT next_day(DATE '2015-07-27', 'Sun');
```

## `timestamp_micros`

Returns the timestamp that is `microseconds` microseconds after 1970-01-01 00:00:00 UTC. Negative values precede the epoch. Unlike DataFusion's `to_timestamp_micros`, only integer types whose full range fits in BIGINT are accepted; floating-point, decimal and string inputs are rejected. The result has microsecond precision and the session time zone (`datafusion.execution.time_zone`, default UTC). The time zone affects display, not the stored microsecond count. Every BIGINT value is valid, including its minimum and maximum. Returns NULL for NULL input.

```sql
timestamp_micros(microseconds)
```

### Arguments

- **microseconds**: TINYINT, SMALLINT, INT or BIGINT count of microseconds since the UTC epoch. Arrow UInt8, UInt16 and UInt32 inputs are also accepted. UInt64 is rejected because its full range cannot fit in BIGINT. NULL returns NULL.

### Example

```sql
> SELECT timestamp_micros(0::BIGINT);
1970-01-01T00:00:00Z
> SELECT timestamp_micros(-1::BIGINT);
1969-12-31T23:59:59.999999Z
> SELECT timestamp_micros(NULL);
NULL
```

## `to_utc_timestamp`

Treats `ts` as a wall-clock time in time zone `tz` and returns the UTC wall-clock time. This is the inverse of `from_utc_timestamp`. DataFusion has no built-in equivalent. A string `ts` is cast to a timestamp, so a string with an offset is first converted to UTC. The result has the same type as `ts`, including any time zone it carries. Returns NULL if either argument is NULL. Unlike `from_utc_timestamp`, `tz` is parsed by Arrow, so it accepts region IDs and `+HH:MM` offsets but not all of Spark's spellings (such as `GMT+1` or `PST`). An unknown zone is an error. Within a few hours of a daylight saving time change, the offset can be taken from the wrong side of the change, so the result can differ from Spark by the size of the change ([#110](https://github.com/apache/datafusion-spark/issues/110)).

```sql
to_utc_timestamp(ts, tz)
```

### Arguments

- **ts**: Timestamp expression, interpreted as a wall-clock time in `tz`. A string is cast to a timestamp. NULL returns NULL.
- **tz**: String time zone that `ts` is in: a region ID such as `Asia/Seoul`, or an offset such as `+09:00`. NULL returns NULL.

### Example

```sql
> SELECT to_utc_timestamp('2016-08-31'::timestamp, 'Asia/Seoul');
2016-08-30T15:00:00
> SELECT to_utc_timestamp('2018-03-13T06:18:23+02:00', 'America/New_York');
2018-03-13T08:18:23
> SELECT to_utc_timestamp('2016-08-31'::timestamp, NULL);
NULL
```

## `trunc`

Returns `date` truncated to the unit given by `fmt`, as a date. Unlike DataFusion's `date_trunc`, it takes the date first and the unit second, only accepts dates (a string is cast to a date), and also accepts Spark's unit aliases `yyyy` and `yy` for year and `mon` and `mm` for month. Returns NULL if `date` is NULL. `fmt` must be a constant string: a NULL or unsupported `fmt` is a planning error, where Spark returns NULL.

```sql
trunc(date, fmt)
```

### Arguments

- **date**: Date expression to truncate. A string is cast to a date. NULL returns NULL.
- **fmt**: Constant string unit, case-insensitive: `year` (`yyyy`, `yy`), `quarter`, `month` (`mon`, `mm`), `week` (truncates to Monday) or `day`, or another spelling of these that DataFusion accepts (such as `months`).

### Example

```sql
> SELECT trunc('2009-02-12'::date, 'YEAR');
2009-01-01
> SELECT trunc('2009-02-12'::date, 'MM');
2009-02-01
> SELECT trunc('2009-02-12'::date, 'WEEK');
2009-02-09
```

## `unix_date`

Returns the number of days since 1970-01-01, as an INT. Dates before 1970-01-01 return a negative number. DataFusion has no built-in `unix_date`. Returns NULL if the input is NULL. The input must be a DATE; strings are not implicitly cast.

```sql
unix_date(date)
```

### Arguments

- **date**: DATE expression. NULL returns NULL.

### Example

```sql
> SELECT unix_date(DATE '1970-01-02');
1
> SELECT unix_date(DATE '1900-01-02');
-25566
> SELECT unix_date(NULL::DATE);
NULL
```

## `unix_micros`

Returns the number of microseconds since 1970-01-01 00:00:00 UTC, as a BIGINT. DataFusion has no built-in `unix_micros`. A timestamp without a time zone is read as UTC, and a timestamp's time zone does not change the result. Any finer part is rounded down (toward negative infinity, like Spark), so timestamps before 1970 with a fractional part move one unit further from zero. Returns NULL if the input is NULL. The input must be a TIMESTAMP; strings are not implicitly cast.

```sql
unix_micros(timestamp)
```

### Arguments

- **timestamp**: TIMESTAMP expression. NULL returns NULL.

### Example

```sql
> SELECT unix_micros(TIMESTAMP '1970-01-01 00:00:01');
1000000
> SELECT unix_micros(TIMESTAMP '1900-01-01 00:00:01');
-2208988799000000
> SELECT unix_micros(NULL::TIMESTAMP);
NULL
```

## `weekday`

Returns the day of the week as an INT from 0 (Monday) to 6 (Sunday). This differs from `dayofweek`, which counts from 1 (Sunday) to 7 (Saturday). DataFusion has no built-in `weekday`. Timestamps are cast to DATE first. Strings are not implicitly cast as they are in Spark ([#41](https://github.com/apache/datafusion-spark/issues/41)). Returns NULL if the input is NULL.

```sql
weekday(date)
```

### Arguments

- **date**: DATE or TIMESTAMP expression. NULL returns NULL.

### Example

```sql
> SELECT weekday(DATE '2009-07-30');
3
> SELECT weekday(TIMESTAMP '2024-01-07 23:59:59');
6
> SELECT weekday(NULL::DATE);
NULL
```
