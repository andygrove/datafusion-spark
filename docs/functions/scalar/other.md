## `bitmap_bit_position`

Returns the bit position of a value within its bitmap bucket, as a BIGINT from 0 to 32767. Spark's bitmap functions split integers into buckets of 32768 values (one 4 KiB bitmap each); `bitmap_bucket_number` gives the bucket. A positive value maps to `(value - 1) % 32768`, and zero or a negative value maps to `-value % 32768`. NULL returns NULL. DataFusion has no built-in `bitmap_bit_position`.

```sql
bitmap_bit_position(expr)
```

### Arguments

- **expr**: TINYINT, SMALLINT, INT or BIGINT expression. NULL returns NULL.

### Example

```sql
> SELECT bitmap_bit_position(1);
0
> SELECT bitmap_bit_position(32769);
0
> SELECT bitmap_bit_position(-1);
1
```

## `bitmap_bucket_number`

Returns the number of the bitmap bucket that a value falls in, as a BIGINT. Spark's bitmap functions split integers into buckets of 32768 values (one 4 KiB bitmap each); `bitmap_bit_position` gives the position within the bucket. A positive value maps to `1 + (value - 1) / 32768`, so 1 to 32768 are bucket 1. Zero or a negative value maps to `value / 32768`, rounded toward zero, so -32767 to 0 are bucket 0. NULL returns NULL. DataFusion has no built-in `bitmap_bucket_number`.

```sql
bitmap_bucket_number(expr)
```

### Arguments

- **expr**: TINYINT, SMALLINT, INT or BIGINT expression. NULL returns NULL.

### Example

```sql
> SELECT bitmap_bucket_number(1);
1
> SELECT bitmap_bucket_number(65537);
3
> SELECT bitmap_bucket_number(-65536);
-2
```

## `bitmap_count`

Returns the number of bits that are set in a binary bitmap, as a BIGINT. NULL returns NULL. DataFusion has no built-in `bitmap_count`.

```sql
bitmap_count(bitmap)
```

### Arguments

- **bitmap**: Binary expression, such as a bitmap built by Spark's `bitmap_construct_agg`. NULL returns NULL.

### Example

```sql
> SELECT bitmap_count(X'1010');
2
> SELECT bitmap_count(X'FFFF');
16
```

## `equal_null`

Returns true if the two arguments are equal or both NULL, and false otherwise. Never returns NULL. Same as Spark's `<=>` operator and DataFusion's `IS NOT DISTINCT FROM`, which it is rewritten to. The arguments are coerced to a common type, so `equal_null(1::int, 1.0::double)` is true; it is an error if they can't be compared. For floating-point values NaN equals NaN and 0.0 equals -0.0, including inside arrays and structs. DataFusion has no built-in `equal_null`.

```sql
equal_null(expr1, expr2)
```

### Arguments

- **expr1**: Expression of any comparable type.
- **expr2**: Expression of a type comparable with `expr1`.

### Example

```sql
> SELECT equal_null(3, 3);
true
> SELECT equal_null(1, NULL);
false
> SELECT equal_null(NULL, NULL);
true
```

## `spark_cast`

Casts `expr` to `type` as Spark's `CAST(expr AS type)` does. The target type is a string literal in Spark's SQL type syntax: BOOLEAN, TINYINT (BYTE), SMALLINT (SHORT), INT (INTEGER), BIGINT (LONG), FLOAT (REAL), DOUBLE, DECIMAL(p, s) (DEC, NUMERIC), STRING, CHAR(n), VARCHAR(n), BINARY, DATE, TIMESTAMP (TIMESTAMP_LTZ), TIMESTAMP_NTZ, and ARRAY<...>, MAP<..., ...> and STRUCT<name: type, ...> of these. Type names are case-insensitive. CHAR and VARCHAR require a length and cast to STRING. INTERVAL, TIME, VARIANT, VOID and the geospatial types are not supported. The cast follows `datafusion.execution.enable_ansi_mode`, as Spark's follows `spark.sql.ansi.enabled`, and uses `datafusion.execution.time_zone` as the session time zone. Casts are being ported from Comet (https://github.com/apache/datafusion-spark/issues/88): a cast that Spark supports but this function does not yet returns a "not implemented yet" error, and a cast that Spark does not support returns a "not supported" error. Returns NULL if `expr` is NULL.

```sql
spark_cast(expr, type)
```

### Arguments

- **expr**: Expression to cast.
- **type**: The target type, as a string literal in Spark's SQL type syntax, such as 'int', 'decimal(10, 2)' or 'array<timestamp>'.

### Example

```sql
> SELECT spark_cast(true, 'int');
1
> SELECT spark_cast(0, 'timestamp');
1970-01-01T00:00:00Z
```

## `stack`

Separates `expr1`, ..., `exprk` into `n` rows of `ceil(k / n)` columns named `col0`, `col1`, ... The values fill the rows in order, and the last rows are padded with NULLs. DataFusion has no built-in `stack`. In Spark, `stack` is a generator that returns rows. A scalar function returns one value per row, so here the rows are returned as a list of structs, which the caller (e.g. Comet, or `unnest` in SQL) is expected to expand. As in Spark, the list is never NULL, but its elements and fields can be. As in Spark, `n` must be an INT from 1 to 2147483647, and the values of a column must have the same type, which is the type of its first non-NULL value. NULLs, Arrow types of the same Spark type (such as `Utf8` and `Utf8View`), and integer literals that fit an INT column are cast to it. Unlike Spark, which accepts any constant `n` (such as `3 - 1`), `n` must be an integer literal, because the return type is planned before expressions are folded. The rows are materialized, so a very large `n`, such as `stack(2000000000, 1)`, is an error.

```sql
stack(n, expr1[, ..., exprk])
```

### Arguments

- **n**: Integer literal number of rows, from 1 to 2147483647.
- **expr**: One or more values to separate into rows. The values of each column must have the same type.

### Example

```sql
> SELECT stack(2, 1, 2, 3);
[{col0: 1, col1: 2}, {col0: 3, col1: NULL}]
> SELECT unnest(stack(2, 'a', 1, 'b', 2));
{col0: a, col1: 1}
{col0: b, col1: 2}
```
